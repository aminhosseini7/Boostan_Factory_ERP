# استقرار ابری Boostan Factory ERP

این نسخه برای حالتی آماده شده که هیچ کامپیوتر یا CMD در کارخانه همیشه روشن نماند.

معماری نهایی:

- **GitHub Pages**: رابط کاربری React
- **Supabase Postgres**: دیتابیس
- **Supabase Edge Function (`erp-api`)**: بک‌اند همیشه‌در‌دسترس
- سیستم لوکال Node/PostgreSQL قبلی فقط برای توسعه باقی مانده است.

## مرحله 1 — استقرار دیتابیس و API روی Supabase

در ریشه پروژه روی `cloud\deploy-supabase.bat` دوبار کلیک کنید. اسکریپت فقط **Project Ref** پروژه Supabase را از شما می‌خواهد. در صورت نیاز، خود CLI رمز دیتابیس را به‌صورت تعاملی درخواست می‌کند. JWT Secret قوی نیز به‌صورت خودکار روی ویندوز تولید و مستقیماً در Supabase ذخیره می‌شود؛ لازم نیست آن را دستی بسازید یا داخل فایل پروژه قرار دهید.

اسکریپت سپس CLI رسمی Supabase را به صورت project dependency نصب می‌کند، پروژه را link می‌کند، migration را اعمال می‌کند و Edge Function را deploy می‌کند.

> هشدار: migration فعلی، جداول آزمایشی ERP را reset می‌کند. این تصمیم برای فاز فعلی پروژه که داده‌های قبلی آزمایشی هستند گرفته شده است.

## مرحله 2 — تست API

بعد از Deploy، آدرس زیر باید پاسخ دهد:

`https://PROJECT_REF.supabase.co/functions/v1/erp-api/health`

## مرحله 3 — GitHub Pages

در GitHub Repository به:

`Settings > Secrets and variables > Actions > Variables`

بروید و یک Repository Variable بسازید:

- `VITE_API_URL` = `https://PROJECT_REF.supabase.co/functions/v1/erp-api`

سپس در:

`Settings > Pages > Build and deployment`

Source را روی **GitHub Actions** بگذارید.

Workflow موجود در `.github/workflows/deploy-pages.yml` با هر Push به `main` یا `factory-v2-final` فرانت‌اند را build و منتشر می‌کند.

## کاربران اولیه

Migration اسامی فارسی و شیفت‌ها را مستقیماً با UTF-8 ثبت می‌کند، بنابراین مشکل `????` در CMD ویندوز وجود ندارد.

- مدیر: بهنام حسینی
- شیفت 22:00–06:00: کامران قلی پور
- شیفت 06:00–14:00: حسن قلی پور
- شیفت 14:00–22:00: محمد قاسمی

رمزهای Pilot همان رمزهایی هستند که برای این پروژه تعیین شده‌اند. پیش از بهره‌برداری واقعی بهتر است رمز مدیر و Secretهای زیرساخت تغییر کنند.

## منطق تولید ابری

اپراتور در شروع شیفت فقط محصول و عدد کانتر را ثبت می‌کند. کانتر شروع شیفت جدید، کانتر پایان شیفت قبلی محسوب می‌شود. اپراتور قبلی تعداد معیوب را ثبت می‌کند و وقتی هر دو داده موجود باشند:

`تولید کل = کانتر پایان - کانتر شروع`

`تولید سالم = تولید کل - معیوب`

فقط تولید سالم به موجودی محصول اضافه می‌شود.

## منطق فروش

اپراتور منتسب به فروش از روی **زمان فروش و جدول شیفت‌ها** تعیین می‌شود. قیمت هر محصول از تاریخچه قیمت در زمان فروش گرفته می‌شود و قیمت تاریخی فروش‌های قبلی تغییر نمی‌کند.
